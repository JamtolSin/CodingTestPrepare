# CodingTestPrepare

Python3 코딩 테스트 공부 기록. 문제마다 `.py` 파일 하나만 작성합니다.

## 저장 경로

| 사이트 | 상대 경로 | ID 확인 |
| --- | --- | --- |
| 프로그래머스 | `programmers/<문제ID>.py` | URL의 `/lessons/` 뒤 숫자 |
| 백준 | `baekjoon/<문제ID>.py` | URL의 `/problem/` 뒤 숫자 |
| LeetCode | `leetcode/<문제ID>.py` | 문제 화면의 숫자 ID |

날짜·난이도·알고리즘별 하위 폴더는 만들지 않습니다. 날짜별 Notion에는 **문제 링크와 위 상대 경로**를 기록합니다. 같은 문제를 다시 풀 때는 같은 파일을 수정하고 이전 풀이는 Git 기록으로 확인합니다. 파일명이 숫자로 시작해도 `python baekjoon/1234.py`처럼 실행할 수 있습니다.

## 하루 공부 흐름

1. Notion의 문제 링크를 열고 지정된 상대 경로에 파일 하나를 만듭니다.
2. Python3로 직접 풉니다. 백준은 표준 입출력, 프로그래머스는 문제에서 요구하는 `solution` 함수, LeetCode는 요구하는 클래스·메서드 형식을 따릅니다.
3. 예제와 직접 생각한 경계값으로 확인하고 온라인 저지에 제출합니다.
4. 저장소 루트에서 아래 명령을 실행합니다. `<상대경로>`와 `<문제ID>`는 실제 값으로 바꿉니다.

```powershell
git status --short --branch
python -m py_compile <상대경로>
git add -- <상대경로>
git commit -m "solve: <사이트> <문제ID>"
git push
```

현재 공부 브랜치는 `study/python-workflow`입니다. 정리 완료 시 이 브랜치를 checkout하고 upstream까지 연결해 둡니다. 다른 브랜치에서 시작했다면 작업 상태를 확인한 후 `git switch study/python-workflow`로 돌아옵니다. 기본 브랜치 병합은 별도로 결정합니다.

5. 대화에 **브랜치 또는 커밋 링크 + 상대 경로**를 보내고 피드백을 요청합니다. 가능하면 저지 결과도 함께 알려주세요. 예: “이 커밋의 `programmers/12906.py`를 검토해 줘. 정답 대신 반례와 힌트부터.” 이 경로는 형식 예시이며 오늘 배정된 문제를 의미하지 않습니다.

push만으로 자동 리뷰가 실행되지는 않습니다. 피드백 요청을 받으면 해당 커밋의 코드와 원문 조건을 확인해 정확성, 반례, 시간·공간 복잡도, 가독성을 검토합니다. 수정 후 같은 파일을 다시 commit/push하면 됩니다.

## 작성 원칙

- 메타데이터 파일, 풀이 설명, 설계 주석, 별도 테스트 파일은 필수가 아닙니다.
- 원한다면 파일 첫 줄에 `# 문제 URL` 정도만 남깁니다. LeetCode는 URL이 slug이므로 링크 주석을 권장하지만 필수는 아닙니다.
- 3회 이상 재사용하지 않는 코드는 불필요하게 함수로 나누지 않습니다. 저지가 요구하는 `solution` 함수·메서드는 작성합니다.
- 추가 패키지 없이 Python3 표준 라이브러리를 기본으로 사용합니다.
- 구문 검사 통과와 예제 통과는 전체 정답 판정이 아닙니다.
